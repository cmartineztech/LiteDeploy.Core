# LiteDeploy Project Status (v2)

**Updated:** 2026-10-15

## Current state

Architecture v2 is the sole Runtime/Admin layout in this repository. Legacy names (`BootInitializer`, `DeploymentEngine`, `LogWriter`, …) are retired as *source* components. Admin.Build still publishes **`LiteDeploy.DeploymentEngine.ps1` as a byte-identical copy of Engine** so existing WinPE BootInitializer images keep working.

### Lab imaging checklist

1. `Admin.Build -DeploymentShare C:\DeploymentShare` (Engine + DeploymentEngine alias + Tools\WinPECT)
2. Confirm `LiteDeploy.Engine.ps1` and `LiteDeploy.DeploymentEngine.ps1` hashes match on the share
3. `Admin.Config` → `BootConfig.json` (`Ui.Theme`)
4. Import OS media + workflow catalog
5. Inject Boot (or legacy BootInitializer) into WinPE; map share as `Z:`
6. Boot → Engine through Disk/Image → handoff → specialize arms HKLM Run → interactive logon → FullOS.ps1

Numbered folders under `Engine\Scripts\` are **not** required on the share when flat publish is present; they are for developers working in this repo.

Deployment lifecycle: ID is assigned immediately before WorkflowSelection launches; deployment share logs are created only after confirmation and target validation. Cancelled/failed selection keeps local diagnostics only.

## Effective configuration after selection (implemented)

WorkflowSelection returns its current BootConfig object in memory, including F5 reloads. After Passed=true, Engine requires that object, adopts it for subsequent phases and BootObject.Config in deployment state, and revalidates ImageEngine before disk preparation. It does not reread the configuration file. Selection JSON and nested SelectionData omit the duplicate BootConfig; state retains its existing BootObject.Config serialization behavior.

DriveSelection=false resolves Disk 0 and requires the confirmed TargetDiskIndex to be 0. Otherwise Engine uses the confirmed nonnegative disk number. Missing returned configuration, invalid target, or a policy/confirmation mismatch stops before deployment-folder creation and disk preparation. The technician must reopen selection and confirm again; Engine never silently substitutes a different disk.

This resolves the previously reported F5/stale-policy target mismatch. Automated checks cover both policy-change directions, disagreement, missing configuration, cancellation and the in-memory/JSON result contract. Real WinPE imaging remains unverified.
